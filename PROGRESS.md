## Цель проекта

Универсальный пайплайн для рекламных изображений предмета в Blender:
пользователь описывает предмет словами и смотрит на картинки с вариантами,
всё остальное делает код. Пользователь не работает в GUI — он смотрит на сетку
вариантов и называет номер.

Основная рабочая модель — управление Blender через агентскую систему
(текстом и референсами), а не через GUI. Открытие живого Blender для ручного
выбора ракурса — второй, опциональный путь. Референсы работают не только
на форму, но и на материалы и свет. Полное описание для README — см. раздел
ниже, готово к использованию как есть.

Пользовательская документация: [README.md](README.md), [GUIDE.md](GUIDE.md),
[LIMITS.md](LIMITS.md).

## Найдено на проверке выполняемости в прошлой сессии — обе молчаливые, обе исправлены

Держать в голове при финальной проверке перед коммитом: `check.py` эти два
бага не ловил, потому что проверяет только «файл создан и не пустой».
Нужен взгляд на картинку, а не только PASS.

### 1. Утверждённый ракурс не работал вообще — `lib/camera.py`

`ensure_camera()` создавала констрейнт `Track To` только при первом вызове
и не переустанавливала цель при повторных. А `shot.restore()` удаляет
`CamTarget` (он в списке `JUNK`). Итог: после `restore()` камера смотрела
вертикально вниз вместо утверждённого ракурса — во всех стадиях `looks`,
`light`, `preview`, `final`. `check.py` это не ловил: вид сверху на плоский
прямоугольник тоже «файл создан и не пустой».

**Исправлено:** цель переустанавливается при каждом вызове `ensure_camera()`
([lib/camera.py:37](lib/camera.py:37)). Проверено рендером до/после.

### 2. Номера вариантов уезжали за кадр — `lib/variants.py`

`label_on()` ставила номер по фиксированным координатам в метрах
(`margin=(0.60, 0.56)`), хотя вся остальная библиотека живёт в долях охвата
кадра. При 85-мм объективе заготовки кадр на рабочей дистанции оказывался
вдвое уже этих чисел — номер рендерился за кадром, лист вариантов выходил
без номеров. А весь способ работы пользователя — «смотрю на варианты
и называю номер».

**Исправлено:** `label_on()` берёт кадр из `cam.data.view_frame()`
([lib/variants.py:22](lib/variants.py:22)) — то же, чем пользуется сам Blender;
`margin`/`size` теперь в долях охвата кадра. Проверено рендером: номера 1–4
видны в кадре.

**Повторная проверка в этой сессии (26.07.2026):** `blender -b --python
template/make.py -- /tmp/tpipe preview` и `... looks` — камера смотрит на
предмет под углом (не сверху вниз), номера 1–4 видны в левом верхнем углу
каждого тайла `looks.png`. Оба бага подтверждены исправленными визуально,
не только по `check.py`.

## Не трогать пока: набор света `editorial_light`

В `lib/lighting.py` лежит незакоммиченный второй набор света — светлый
разворот для матового/светлого предмета, противоположность `editorial_dark`.
Нигде не вызывается, на работоспособность пайплайна не влияет, можно
коммитить как есть (мёртвый код) или вырезать — на усмотрение новой сессии,
явного запрета уже нет, но и явного запроса доделать тоже не было.

Известное на нём: первая редакция давала пересвеченную плоскую картинку
(AgX сжимал всё в узкую светлую полосу из-за почти сплошной эмиссии фона
при `falloff=1.4`). После снижения уровней источников втрое и переноса
хотспота фона за предмет (`hotspot=(0.0, 0.05)`, `falloff=1.00`,
`backdrop_base=0.38`) сетка вариантов дала нормальный светлый разворот —
**но подтверждающий рендер после последней правки констант не запускался**,
считать набор проверенным нельзя. Отдельно: ни `editorial_dark`, ни
`editorial_light` не дают контактной тени — в `backdrop()` только задник,
пола нет.

## Найдено рендером, не рассуждением (исторический раздел, не удалять)

Десять ошибок за всю историю проекта, четыре из них — молчаливые: код
не падал, а выдавал правдоподобный неверный результат. Самый частый
и самый дорогой класс ошибок в этом проекте.

1. **`snap_to_viewport()` в фоне отдавал стартовый ракурс.** При `blender -b`
   область VIEW_3D в данных всё-таки есть. Теперь проверяется
   `bpy.app.background` и бросается ошибка.
2. **`frame.extent()` считал источники света частью предмета.** Габариты
   раздувались втрое. Отсекаются по `visible_camera`.
3. **`frame.fit(by="height")` срезал широкий предмет** на вертикальном кадре,
   `by="width"` врал на любом неквадратном кадре. Пересчёт через пропорции
   кадра, по умолчанию `by="max"`.
4. **`blender -b` без файла грузит стартовую сцену** — куб и лампа попадали
   в кадр. Отсюда `scene.reset()` первой строкой каждого `make.py`.
5. `BLENDER_EEVEE_NEXT` не существует в Blender 5 — движок снова
   `BLENDER_EEVEE`.
6. `check.py` брал первую строку с префиксом `SMOKE ` вместо вердикта.
7. Ожидания теста по пассам были неверны: префикс `ViewLayer.`,
   AO — `Ambient Occlusion`, не `AO`.
8. `py_compile` с `cfile=os.devnull` падает на Python 3.14.
9. **`ensure_camera()` не переустанавливала цель `Track To`** — см. выше.
10. **`label_on()` жила в метрах, а не в долях кадра** — см. выше.

## Принципы, на которых всё держится

* **Смотреть, а не рассуждать.** Превью — 5 секунд, сетка вариантов — 9.
* **Утверждённые числа — в код,** а не в `.blend`: файл мог быть сохранён

  сцена в `smoke.py` намеренно не похожа на заготовку.

  ДО отправки.** Публичный пуш плохо откатывается — этот урок стоил
